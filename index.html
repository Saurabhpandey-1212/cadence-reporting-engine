What it does

Collects

It pulls each brand's numbers straight from the advertising, analytics, search and store systems — no exports, no spreadsheets, no copy-paste.

Checks

Platforms rarely agree with each other. The system settles those differences the same way every time, and clearly flags anything it can't settle rather than quietly picking a number.

Explains & publishes

It writes the commentary, verifies every figure in that commentary against the calculated data, and only publishes once its own quality checks pass.

    How it works

    Five stages, start to finish, with no one in the middle.

    1. 1

      Gather

      Reads every connected platform at once, and picks up where it left off if one is slow or down.

    2. 2

      Reconcile

      Puts nine different definitions of the same number onto one common footing.

    3. 3

      Calculate

      Every figure in the report is computed in code — never written by the AI layer.

    4. 4

      Write

      An AI layer explains what changed and why, working only from those calculated figures.

    5. 5

      Verify & publish

      Automated checks re-test every figure and claim. Anything that fails blocks publication.

    The one rule the whole design rests on: the AI is allowed to judge and explain, never to do the arithmetic. Numbers come from code; the commentary is checked against those numbers before anything reaches a reader.
    For technical readers
    • Python service with async fan-out across nine upstream APIs — bounded per-source concurrency, retry with backoff, and content-addressed caching so an interrupted run resumes instead of restarting.
    • A typed deterministic metric engine produces every published figure. No metric is ever generated by a language model.
    • The reasoning layer receives computed metrics and returns schema-validated JSON only — never prose, never a figure of its own.
    • Validation gates cover schema conformance, numeric cross-checks against the computed data, coverage floors, audience policy and claim rules. A failure blocks publish and triggers a bounded repair loop.
    • Partial upstream failure degrades the report with an explicit coverage note; nothing is silently estimated.
    • Every run is journalled, so any published figure can be traced back to the payload it came from and replayed.

    Deliberately high level. The source code, prompts, schemas, reconciliation rules and thresholds are proprietary and not published here, and no client data or credentials appear anywhere in this repository.
